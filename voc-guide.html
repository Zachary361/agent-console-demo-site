平台 v5 · Agent契约 v2 · 2026-11-02

已实现真实条件路由、逐条规则处理、人工标签复核、双角色确认及持久化演示任务。未调用真实模型或视觉服务；Prompt和模型输出Schema可编辑并保存，当前规则执行器不会理解自由改写的Prompt。规则分数未经校准，不是模型准确率。图片只能人工核对；族裔只记录自述，价格表达不等于财富。

1. 使用顺序

  1. Agent治理选择「VOC 评论打标」，选择最新v2版本并打开「多场景编排」。旧v1及自建Agent保留。
  2. 双击「逐条问题与情感抽取」「场景搭配与自述提取」「证据与置信度校验」，可看各自System/User Prompt及模型JSON输出约束；阈值和全部复核开关会真实影响分支。
  3. 运行参数 → 填入虚构样例 → 校验运行。8条样例包含中文、英文褒贬混合、图片、履约和空内容。
  4. 运行停在人工标签复核，点「进入标签复核」。对英文混合评论核对后接受；示例图片无法读取时选择排除并填写原因。可添加/移除标签，每个标签需原文或人工图片依据。提交全部复核后恢复运行。
  5. 打开「VOC 款式改善与工单」最新v2画布；运行参数选择刚才的打标结果，系统放入 tagged_batch。可补商品说明、观察期和历史问题备注。
  6. 运行后查看问题排序、产品/运营/待观察去向、根因假设与验证方案。设计师和企划分别确认同一修订后创建演示PLM任务。修改优先级/建议/验收/责任角色会清空旧确认，需重提。
  7. 运行追踪可看实际经过哪些分支；完整JSON包含工单与任务引用。纯好评或只有运营问题直接出报告，无产品工单。

面试推荐：先用欢迎语讲通用Agent/契约/画布/Run，再用VOC展示不同输入分流、AI候选与人工决策的边界。这里的演示角色由同一访客切换，不代表企业双人身份认证。

2. 为什么这样拆分画布

把数据清洗、识别、质量判断和业务副作用拆开，才能知道问题出在哪一步，按步骤换模型/改Prompt/改规则。逐条处理保留review_id，不能把多条评论揉成一段再丢失证据。图像能力不可用时走人工出口；不把无法识别当成无问题。

3. Input / Output Schema怎么写

Schema规定数据长什么样；运行参数JSON是这次真实填什么。把Schema放在新建/版本契约中，把示例数据放在运行参数中。节点的 model_output_schema 只管该次模型步骤，Agent的 output_schema 管最后交付，两者不能混用。

关键字用途本例
type类型object对象、array列表、string文字、integer整数、number小数、boolean真假、null未知
properties定义字段review_text是原声、rating是星级
required必须出现的字段batch_id、style_code、reviews
items数组内每一项规则reviews是一组评论，issue_tags是一组问题
enum固定字典选项一级五类；二级与tag_code需成对校验
minimum / maximum数值范围rating 1–5，helpful_count≥0
additionalProperties:false阻止拼写错误悄悄丢失rating写成rate会报错
type:[number,null]明确未知身高未知为null，不能填0或猜测

本Demo支持基础Schema关键字，不支持$ref/oneOf等高级语法。结构合法不等于语义正确：原声证据、去重、字典组合、审核修订还需服务端业务校验。

场景处理避免的问题

图片/纯图片记录未识别并转人工；无法读取可排除不编造视觉证据
非服装/未知语言/未映射明确非服装排除；未知语义转人工不强塞其他问题
