VOC 双 Agent · Schema 与使用教程

评论原声 → 结构化标签 → 按款归纳 → 双方确认 → 演示 PLM 任务

当前使用可解释的关键词规则，未接真实 AI 模型。图片只保存链接，不读取图片内容；所有标签需人工核对。人种/族裔仅记录用户主动自述；价格表达不代表个人财富或实际消费能力。

1. 两个 Agent 怎么用

  1. 在「Agent 治理」选择「VOC 评论打标」，点「在画布打开」。画布是开始 → VOC 评论打标 → 结束。
  2. 点击「运行参数」→「填入虚构样例」，按款号填写评论后校验并运行。结果可展开查看标签、原声证据、场景与自述信息。
  3. 在治理页打开「VOC 款式改善与工单」。在运行参数中选择刚才完成的打标运行，点击「使用这次打标结果」。
  4. 运行第二张图：归纳排序 → 创建工单 → 人工确认。运行会停在确认节点，进入「审核工作台」。
  5. 查看频次、低星、严重度、点赞和证据。必要时修改优先级/建议并填写原因，保存后重新提交。修改会清空旧确认。
  6. 分别切换设计师、企划角色确认同一修订。只有双方都通过后才恢复画布并创建演示 PLM 任务，可查看任务 ID、源工单、款号、处理建议及责任角色。

也可用「新建 Agent」选择两种 VOC 模板，系统自动带入可编辑契约与独立编排图。需要从头搭建时选择空白画布并添加上述节点。

2. Schema 是规则，input 是本次填写的数据

input_schema 规定调用方必须提供哪些字段、类型及取值范围；output_schema 规定流程最终必须返回什么结构。把 Schema 粘贴到新建向导的契约框，把实际评论 JSON 粘贴到运行参数框。

关键字怎么写为什么
typeobject / array / string / integer / number / boolean / null对象、列表、文字、整数、小数、真假、未知值
properties字段名对应一份规则说明每个字段的含义和限制
required["style_code","reviews"]字段必需出现；非空还需 minLength
items数组中每条评论的规则一批多条评论，避免重复设计字段
enum固定选项列表一级标签只能是约定的五类
minimum / maximum星级1–5、点赞≥0阻断无效数值
additionalPropertiesfalse拼错字段及时报错，避免静默丢弃
type: ["number","null"]有依据填数字，否则 null未知不是0，也不需要编造一个值

本 Demo 支持上述基础关键字；不支持 $ref、$defs、oneOf 等高级契约语法。字段的 default 是示例提示，不保证服务端自动补值。

3. 第一位 Agent 的输入怎么写

一批一个款号，最多50条评论。review_id 用于去重；rating 是数值，不要写成 "五星"。没有图片填 []；用户名或地区未知可填空字符串。self_reported 是可选对象，只放用户明确自述；身高用厘米、体重用公斤，不能混单位。

4. 第一位 Agent 的输出怎么写

一条评论可能同时反映多个问题，因此 issue_tags 是数组，每项成对保存一级/二级标签。场景、搭配、体型、族裔自述和价格表达是独立维度，不塞进五类问题标签。每条问题都有原声 evidence，便于人工复核。

一级标签短二级标签
面料起球、扎肤、闷热、太薄、缩水
尺码偏大、偏小、尺码不准
版型肩部不合、腰部不合、袖长不合、衣长不合、裤长不合
质量开线、破损、拉链故障、褪色
其他问题异味、色差、包装问题、发错货、价格偏高

未匹配问题时 issue_tags=[]；身高体重未知用 null；场景与搭配未知用 []；族裔用“未知”、source=unknown。当前不推断这些属性。

5. 第二位 Agent：承接输出，生成可确认的改善任务

第二位 Agent 的 input_schema 与第一位的 output_schema 相同，可原样承接 style_code、tagged_reviews 等字段。系统按评论 ID 去重；重复 ID 内容冲突时要求修正。一级/二级组合及证据会再次校验。

排序默认：40×问题评论占比 + 30×该问题低星占比 + 25×严重度/3 + 5×min(点赞总数/20,1)。低星默认≤2，权重合计100，可在归纳节点配置。P1≥70，P2≥40，其余P3。这是演示规则，正式投产应按业务数据校准；样本中的问题频次不等于销量口径的缺陷率。

待确认时运行状态为 waiting_human，方案 ID 是中间结果；双方确认并创建演示任务后，结束节点才按 output_schema 验证最终输出。

  "plan_id": "voc_example",
