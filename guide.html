演示使用说明

Agent 中台是一套用于搭建、调试和管理 Agent 的工具。你可以为不同业务任务创建独立 Agent，定义输入输出，通过画布组织处理步骤，再查看每次执行的结果与过程。欢迎语、图生视频、VOC 和智能客服 是这套通用流程中的不同案例。

无需 SSO 即可进入。示例使用虚构数据；部分流程已接入演示后端，其他模块用于展示平台设计，具体可用范围见下文。

跑通一个示例

  1. 打开「Agent 治理」，选择「欢迎语演示」，点击「在画布打开」。
  2. 查看「开始 → 模板输出 → 结束」三个节点。双击节点可以查看配置。
  3. 点击「运行参数」，输入 {"name":"演示访客"}，再点击「运行编排」。
  4. 查看节点状态和返回的欢迎语，进入「运行追踪」，选择本次运行，查看节点输入、输出与耗时。
  5. 拖动节点调整布局，点击「保存草稿」。刷新后重新进入该画布，可以继续查看和运行。

这个示例使用模板规则生成结果，不调用大模型。它用于理解输入、节点、连线、输出和运行记录之间的关系。

测试客服多 Agent 编排

选择「智能客服 · 多 Agent 总控」→「运行参数」→ 选择「多意图 · 快慢分流」→「填入场景」→「校验输入」→「运行编排」。请勿把总控参数直接用于六个专职子 Agent，它们的输入契约不同。

运行后切到「协作运行」，检查洗护先答、订单核验后再答，以及每个子 Agent 的结果。双击节点，在输入输出配置中检查来源、字段与下游；「试运行」页签显示实际运行数据。

搭建自己的 Agent

明确任务 → 注册 Agent → 定义输入输出 → 画布编排 → 校验并保存 → 试运行 → 查看追踪 → 迭代版本

  1. 明确任务：先说明给谁用、接收什么信息、完成哪些步骤、最后交付什么结果。
  2. 注册身份：在「Agent 治理」点击「新建 Agent」，填写唯一编码（例如 demo.my_assistant）、名称、用途与责任信息，按任务选择空白画布或示例模板。
  3. 约定输入输出：下一步设置输入契约、输出契约和独立编排图。契约规定字段、类型与必填项；运行参数填写的是某一次任务的实际数据。
  4. 配置画布：添加所需节点，双击编辑参数，从输出圆点拖向下一节点完成连线。执行顺序由连线决定。点击连线可在画布下方摘要中删除；看不到节点时点击「适应」。
  5. 传递数据：节点读取 input.* 或上游变量，将结果写入 variables.*；结束节点从指定来源路径读取最终结果。上下游路径需要一致。
  6. 保存与运行：保存节点配置，再点击画布「校验」和「保存草稿」。打开「运行参数」，按当前 Agent 的契约填写输入，校验后运行。
  7. 排查与迭代：在运行检查器或「运行追踪」查看状态、输入输出及错误。需要固定新的契约和编排绑定时，在治理页创建 Agent 新版本。

一个 Agent 是可复用的任务能力，一张编排图描述其处理步骤，每次提交输入会产生一次独立运行。保存图草稿与创建 Agent 版本是两个动作；画布试运行执行当前图快照，直接版本调用使用该版本绑定的图修订。

各模块在整体框架中的作用

以下说明平台的职责划分与设计目的，不代表每个模块都已接入真实执行能力。

Agent 治理与契约：让任务能力有统一身份
管理用途、责任、输入输出和版本，让调用方知道如何使用，让维护者能追溯变更。
编排画布与节点：把任务拆成可配置步骤
用节点表达处理动作，用连线表达顺序，用变量路径传递数据，让业务流程可以检查和调整。
模型、Prompt、技能工具与知识库：复用底层能力
分别负责模型调用、指令模板、系统操作和资料检索。将这些资源独立管理，便于多个 Agent 共用及按需替换。
触发器、执行与运行追踪：让流程可运行、可定位
平台设计包含手动、接口或事件触发；执行层负责处理任务，追踪层记录每一步发生了什么。当前可体验手动画布运行。
评测、发布、权限与审核：控制变化和使用范围
用于判断版本质量、管理上线范围、授权访问和引入人工确认。这些治理模块目前主要保留原型设计。

案例：同一套工具，不同的任务

欢迎语：理解最小输入输出流程

输入姓名，模板输出节点读取 input.name，把欢迎语写入变量，结束节点返回结果。适合先认识画布和追踪。

图生视频：体验异步任务和文件结果

新建时选择图生视频模板，或在空白画布连接「开始 → 图生视频 → 结束」。视频节点输出路径与结束节点来源均使用 variables.video。在节点中设置时长、画幅和镜头，在「运行参数」上传图片或使用示例图片。执行成功后可在检查器与追踪页播放、下载。

当前视频是 FFmpeg 图片镜头动效，提示词仅记录，未接 AI 视频模型。它用于验证文件输入、后端执行和结果交付这一类流程。

知识问答、反馈分析、内容生成和业务处理助手等，是这一框架可以继续探索的应用方向；需要为具体场景接入模型、资料或工具并验证，当前不代表这些应用已完成。

智能客服进阶：一个总控与六个专职 Agent

从「智能客服 · 多 Agent 总控」进入画布，按问题调用会话理解、知识核验、订单核验、答案组织、答复质检与人工交接 Agent。每个职责都有独立契约和子画布。

13种场景可演示并行核验、先答已知问题、政策冲突、有限修复、超时恢复和客户确认。进入总控。长画布可用专注模式和1:1缩放查看节点，未接真实模型与渠道。

智能客服：多语言、多意图与等待回应

「多语言智能客服」按会话隔离客户，归并连续消息与重复意图；明确问题先答，慢查询保留待答，长等待自动安抚或转人工。可切换汇总、逐意图或混合回复方式。

运行后从编排结果进入模拟收件箱，查看原声、意图、回复时间线和人工接管。四语规则演示，未连接模型或真实渠道。查看客服流程、Schema、Prompt与指标 →

VOC：从评论打标到双确认改善工单

「VOC 评论打标」与「VOC 款式改善与工单」是两个同级 Agent：前者接收同款评论，输出短问题标签与证据；后者按款归纳排序，创建工单并停在人工确认节点。设计师与企划两个演示角色确认同一修订后，画布继续创建演示 PLM 任务。

在第二个 Agent 的运行参数中选择前一个打标运行，即可带入结果。标签使用规则演示，图片只保留引用，没有接入真实模型或真实 PLM。查看使用流程与 input/output schema 写法 →

概览指标怎么看

概览用于判断任务是否顺畅运行，并找到下一步要处理的问题。先看运行量，再看成功率与耗时，最后定位排队、审核和失败原因。

24h 运行：有没有在使用、负载有多大
统计时间窗口内的运行次数，用来观察使用变化。一次业务任务可能发生多次重试，因此运行次数不能直接等同于完成的业务任务数。附带的 Token 表示模型用量，不直接等于费用。
成功率：流程是否可靠
关注已结束的运行中有多少执行成功。成功表示系统按约定完成处理，结果是否正确、是否被用户采用，还需要另外评估。正式统计应明确取消任务的处理口径。
P95 延迟：较慢的一批任务体验如何
约 95% 的耗时样本不超过这个值，帮助发现平均耗时掩盖的长尾等待。欢迎语与视频应分场景比较，并区分排队、执行和人工等待时间。
队列任务：处理能力是否跟得上需求
结合最老等待时间与 Worker 容量，判断是否积压，再决定扩容、限流或调整任务优先级。短暂排队不一定是故障。
待人工审核：人机协作是否卡住
显示需要人做决定的任务，重点看等待时长和超时情况。必要审核是质量控制的一部分，不应为了清零而省略。
失败运行：有多少次执行需要处理
用绝对数量判断影响面，结合成功率判断严重程度；进入追踪按 Agent、版本、节点和错误类型定位，再决定修正或重试。

运行环境、Worker、Agent 健康排行和最近失败用于定位原因；评测与发布状态用于观察版本变更风险。这些是诊断信息。衡量平台价值还应看首次成功运行率、搭建耗时、达到业务验收标准的任务完成数，以及每个可用结果的成本。

当前概览保留了正式平台的指标布局，但运行汇总来自本浏览器最多 30 条欢迎语演示记录，尚未按当前 Agent 和近 24 小时完整筛选；队列及环境状态主要是演示值或空态；VOC 待审核数读取演示后端，包含标签复核批次与改善方案。新建 Agent 的后端运行尚未汇入这套完整统计，请到「运行追踪」查看实际任务。页面数值不能作为真实业务规模、SLA 或模型质量的证明。

可做与未接入

当前可创建 Agent、定义契约、编辑并保存顺序和布尔条件分支编排、填写运行参数、保存本地测试用例、执行模板或视频示例、查看节点输入输出和运行结果。后端运行支持取消和按原快照重试。

可执行节点包括开始、模板输出（mock）、图生视频、VOC 打标/归纳/工单、双角色确认、演示 PLM 和结束；每张图最多一个视频节点。VOC 支持图片与质量条件分流、人工标签复核、无产品问题直接出报告，以及改善审核退回、修改重提和等待状态恢复；每图最多 30 节点、40 连线。未接企业身份权限或真实 PLM。循环、自然语言自动搭建、真实模型调用、知识检索、其他企业工具、评测、触发器及生产发布尚未接入。

数据、重置与连接

原欢迎语的编排、测试用例与模拟运行保存在当前浏览器。新建 Agent、图版本及后端运行保存在对应的匿名工作区；输入图片内容不会写入测试用例或运行日志，上传素材和生成文件保存在演示后端。

顶部「重置欢迎语示例」只重置浏览器欢迎语示例，不删除后端工作区。清除站点数据会丢失匿名工作区入口。演示数据不自动过期，请使用示例或非敏感素材。

请使用桌面浏览器。公开页面可直接访问；当前后端使用临时通道，依赖演示电脑和进程持续运行。若连接失败或注册表只显示欢迎语，可在治理页点击「重新连接」。本地完整启动方式见源码仓库 README。
